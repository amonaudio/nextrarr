📖 Legenda badge

Risoluzione:
  • SD = 480p / 576p
  • HD = 720p
  • FHD = 1080p
  • 4K = 2160p
Codec video:
  • H264 = x264 / H.264 / AVC
  • HEVC = x265 / H.265 / HEVC
  • Xvid = Xvid / DivX (vecchio)
  • — = info non disponibile
Audio canali (opzionale):
  • 2.0 = stereo
  • 5.1 = surround
  • 7.1 = 7.1 surround
Sorgente (opzionale):
  • BluRay, WEB-DL, HDTV, ecc.
  • Possibile terzo badge per la sorgente del rilascio

3. Piano di implementazione

📋 Modifiche tecniche necessarie

  1. Estendere il tipo ArrMedia in src/lib/services/radarr-sonarr.ts: aggiungere movieFile?: { quality, mediaInfo } (Radarr) e statistics?: { ... } (Sonarr — non include mediaInfo, lasciamo — per ora).
  2. Estendere MediaItem in src/lib/types.ts: aggiungere campi resolution (string, es. "4K" / "FHD" / "HD" / "SD"), video_codec (string, es. "HEVC" / "H264"), e opzionalmente audio_channels (string, es. "5.1").
  3. Aggiornare /api/media/[type]/route.ts: estrarre movieFile.mediaInfo.videoCodec + movieFile.quality.quality.resolution da Radarr e mapparli a short labels. Mapping function in un nuovo file src/lib/media-info.ts con funzione resolutionLabel(num) → "SD" | "HD" | "FHD" | "4K".
  4. Aggiornare MediaCard: aggiungere i 2 badge in basso-sinistra del poster (sovrapposti con absolute bottom-1 left-1).
  5. Ridisegnare ArtworkModal: cambiare max-w-3xl → max-w-6xl, layout grid lg:grid-cols-3 per affiancare le 3 sezioni. Sostituire 🖼️ emoji con ImageIcon di lucide-react. Miniature h-48 invece di h-20.
  6. Nuovo route /api/upload-artwork/[type]/[id]: riceve multipart/form-data con un file image, lo valida (whitelist mime jpg/png/jpeg, max 10MB), lo salva con nome {folderName}-{type}.ext sovrascrivendo il file locale esistente. Invalida folderCache.
  7. Aggiungere pulsante "Carica da PC" in ArtworkModal: <label> con <input type="file" accept="image/*"> nascosto che, sul change, fa fetch POST /api/upload-artwork con FormData. Drag&drop bonus con onDrop handler.
  8. Per Sonarr (serie TV): per ora mostriamo badge "—" perché la lista base non ha le info file. Possiamo aggiungere in futuro una fetch lazy /api/v3/episodeFile?seriesId=X per ogni serie, con debounce/cache per evitare N chiamate. Possibile come follow-up.

⚠️ Attenzione alle regressioni

  • • MediaCard ha già overlay icon in top-left/right — i nuovi badge vanno in bottom-left per non collidere
  • • ArtworkModal ha già onPointerDownOutside={(e) => e.preventDefault()} — non toccare per non riattivare il bug del click-outside che chiudeva la modale
  • • scanLocalArtwork ora include poster + fanart (fix v0.7.13) — l'upload deve rispettare le stesse keyword nella naming convention {folderName}-{type}.{ext}
  • • Cache-Control: no-store middleware (v0.7.13) fa già sì che dopo l'upload la card si aggiorni con "Aggiorna libreria"
  • • Validazione server-side del file upload è obbligatoria (whitelist mime + magic bytes + size limit) per evitare upload arbitrari nella cartella media

📦 Release planning

Queste modifiche sono abbastanza sostanziose (5-6 file da modificare + 2 file nuovi + 1 route nuovo) → propongo di rilasciarle come v0.8.0 (bump di minor) invece di v0.7.14 (patch). Questo per segnalare che ci sono nuove feature visibili all'utente, non solo fix.

Stima tempi implementazione: ~3-4 ore di lavoro. Stima test manuali: ~30 min (verificare upload, badge, layout su mobile e desktop).

4. Decisioni da prendere prima di implementare

❓ Q1: Badge audio canali (5.1 / 7.1) — vuoi includerli?

Sarebbe un terzo badge rosso sotto risoluzione + codec. Utile se hai un impianto surround e vuoi vedere a colpo d'occhio quali titoli hanno 5.1 o solo stereo. Aggiunge ~50 byte in più al payload JSON per card.

→ Default: SI, includi (terzo badge opzionale, nascosto se info mancanti)

❓ Q2: Serie TV Sonarr — come gestire l'assenza di info?

Opzione A: Mostra badge "—" grigio come placeholder (zero cost, info non disponibili).
Opzione B: Fetch lazy per ogni serie aperta — fetch aggiuntiva a /api/v3/episodeFile?seriesId=X, rallenta il primo caricamento di ~50ms per serie.
Opzione C: Fetch batch in background dopo il primo caricamento (refresh automatico delle info dopo 5s).

→ Default: Opzione A (placeholder grigio, zero overhead)

❓ Q3: Upload artwork — sovrascrivi o aggiungi?

Quando l'utente carica un'immagine con lo stesso nome di un artwork locale esistente (es. già presente WALL•E-poster.jpg), l'upload lo sovrascrive o crea un nuovo file con suffisso (es. WALL•E-poster-2.jpg)?

→ Default: SOVRASCRIVI (comportamento atteso per "sostituisci l'artwork locale")

❓ Q4: Posizionamento badge risoluzione — dove sulla card?

Opzione A: bottom-left del poster (sovrapposto all'immagine, come nell'header). Opzione B: nel footer della card, sotto l'anno (non sovrapposto). Opzione C: in alto, sotto le icone editor/theme.

→ Default: Opzione A (bottom-left del poster — occupa spazio già "morto" dell'immagine)

❓ Q5: Versione — v0.7.14 o v0.8.0?

v0.7.14 = patch fix (user-facing changes minimi). v0.8.0 = minor bump con nuove feature (badge + upload). Segnala agli utenti di Unraid che c'è roba nuova.

→ Default: v0.8.0 (3 nuove feature user-facing meritano minor bump)
