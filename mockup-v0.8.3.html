0 · Come ho interpretato la richiesta

1. Tooltip

Tutti i tooltip dell'app (header, card, player, eventuali nuovi controlli) devono comparire dopo 3 secondi. I title nativi del browser non sono controllabili via CSS/JS: se vuoi, li convertiremo in tooltip shadcn solo dove sono azioni.

Nota tecnica: il delay va centralizzato in un unico provider globale.

2. Titoli appena aggiunti

Badge visibile solo per i titoli con date_added recente e, preferibilmente, con almeno un'azione mancante (tema, artwork extra o trailer). Il badge sparisce da solo quando il titolo è completo o invecchia.

Nessuna nuova API: il dato date_added è già presente in ogni MediaItem.

3. Filtri e link

Filtri client-side per tipo artwork, senza richieste aggiuntive. I nomi delle tre sezioni diventano cliccabili: cartella locale, pagina Fanart.tv e pagina TMDB del titolo.

Vincolo: un browser non può aprire il Finder/Explorer del server. Per “cartella locale” servono opzioni diverse, illustrate sotto.

Limite “cartella locale”: l'app gira nel container/server. Un link file:///mnt/user/... viene bloccato dai browser moderni quando la pagina è servita da HTTP. Le opzioni L1–L4 sotto mostrano le alternative tecnicamente affidabili.

FEATURE 2

Badge sui titoli appena aggiunti

Il badge è derivato lato client da date_added e dai flag già disponibili (has_theme, has_artwork, has_trailer). Nessuna modifica alle API Radarr/Sonarr.

2a · Quando considerare un titolo “nuovo”

Regola automatica comune
Il badge scompare quando il titolo diventa completo o supera la soglia scelta, senza bisogno di “segna come letto”. Nessuna scrittura su DB.

4 · Impatto tecnico e prevenzione regressioni

File toccati (previsti)

  • src/components/ui/tooltip.tsx + src/app/layout.tsx
  • header.tsx, media-card.tsx, media-player.tsx (rimozione provider locali)
  • media-card.tsx (badge NEW, solo UI)
  • artwork-modal.tsx (filtri + header cliccabili)
  • src/lib/services/artwork.ts (riconoscimento tipo locale)
  • Nuovo endpoint link esterni + endpoint cartella read-only

Cosa non cambia

  • Download, upload ed eliminazione artwork
  • Cache media/folder e refresh
  • Filtri, sort e ricerca della libreria
  • Demo mode e dati mock
  • API key, path mapping e sicurezza esistente

Test prima della release

  • Tooltip su header, card e player: nessuno prima di 3 s, nessuno bloccato
  • Badge: nuovo/completo/vecchio, demo con date aggiornate
  • Filtri: conteggi, empty state, upload/delete e refresh
  • Link: Radarr e Sonarr, ID mancante/fallback, path non valido
  • Regressione modale: zoom, drag&drop, delete, scroll indipendenti
  • npm run build, tsc --noEmit, ESLint sui file toccati
Nota sicurezza: l'endpoint “cartella” sarà read-only, riuserà resolveLocalPath + validateLocalPath, non permetterà path arbitrari e non esporrà file fuori dalla cartella del media. L'endpoint link esterni non restituirà API key.
